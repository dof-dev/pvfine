# 强化、增幅与锻造

目标路径：强化 `etc/upgrade.etc`，增幅 `etc/amplifyupgrade.etc`，锻造 `etc/upgrade_separate.etc`。先核对表布局与版本，以下列索引均从 0 开始。

## 强化与增幅

存在 `[table type]` 时，按 table 自己的 type 值选择 `normal`（强化）或 `amplify`（增幅），不是全文件找到任一 type 后套给所有表。type 后的数值可能仍归在未闭合的 table type 子 section 下，读取时不能只数 table 的直接值。重复匹配、缺失匹配要停止。无 type 的旧格式仅在唯一 table 时接受。

|布局|每级宽度|失败率|失败操作|降级参数|材料ID|数量|
|---|---:|---:|---:|---:|---:|---:|
|旧表|17|6|7|8|9|10|
|typed 武器|24|8|10|11|14|15|
|typed 防具|24|9|12|13|14|15|

表内第一个数值行对应 +1；旧 GUI 最多展示 31 行，超出部分保留。原始失败率 F 为 0～100000 的整数，成功率百分数 P 的写入公式是 `round((100-P)*1000)`，不是 P×100，也不是成功率字段。武器/防具概率和失败处理独立，材料共用。失败操作合法值 1～3，具体语义先查枚举；从降级操作 2 切换到其他操作时把降级参数清零。其余可编辑成本应为非负 32 位整数。

`[safe upgrade]` 每条 8 个整数：列 0 是原等级（GUI 显示 +原等级+1），列 2 失败率、列 3 失败补正原始值、列 5 材料 ID、列 6 数量、列 7 金币。列 1、4 保留。安全强化输入的是失败率，百分数乘 1000；不要套用普通强化的成功率转换。按原等级筛选行，而非假定行序号就是等级。

## 锻造

`[table]` 每级 4 项：属性系数 A、属性系数 B、成功率、材料消耗倍率。成功率原值 0～10000，百分数 P 对应 round(P×100)。A/B 在 GUI 只读，未要求时保留。倍率与系数可能为浮点，保留类型。

`[separate upgrade max]` 唯一整数，范围 1～表行数。`[item weights by grade]` 及可选 `[item weights by grade 100lv]` 每条为装备等级、材料 ID、数量基数；装备等级递增且大于 0。材料实际消耗还受锻造倍率等参数影响，不能把数量基数直接描述成最终成本。保留其他 section。

预览时分别说明概率口径、等级、武器/防具范围、材料与金币变化，再应用并读取验证。

操作前阅读 [MCP 操作流程](references/mcp-workflow.md)，按其查询、验证、预览、应用和保存规则执行。
