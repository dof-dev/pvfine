# JavaScript 脚本工作区

脚本工作区使用 Goja 在进程内运行 `.pvf.js`。脚本只能操作当前打开归档的虚拟文件，运行阶段写入隔离事务；运行成功后生成预览，只有点击“应用选中”才会写入当前工作区 Overlay。应用后仍需通过归档编辑器的保存操作写回 PVF 文件。

## 最小示例

```js
for (const file of pvf.glob("equipment/**/*.equ")) {
  const document = file.parse();
  const price = document.section("price");
  if (price && price.get() < 10) {
    price.set(10);
    file.write(document);
  }
}
```

`sections(path)` 返回精确路径的全部 section；`section(path)` 和 `get/set/delete` 默认只访问第一个匹配项。重复 section 必须显式遍历 `sections()` 或传入 `occurrence`。替换已有值时保留原 token 类型；新增字符串默认是带引号字符串，新增数字按整数/浮点范围推断。

需要精确控制 token 类型时传入值对象：

```js
document.set("price", { type: "float", value: 3.5 });
section.set({ type: "quoted", value: "展示名", pool: "utf16" });
```

## 新建、复制与删除文件

```js
const created = pvf.createFile("equipment/new.equ", pvf.types.script, "[price]\n100");
created.setText("[price]\n200"); // 之后可继续编辑

pvf.copyFile("equipment/a.equ", "equipment/b.equ");        // 目标已存在时报错
pvf.copyFile("equipment/a.equ", "equipment/b.equ", true);   // 显式覆盖

pvf.deleteFile("equipment/old.equ"); // 返回是否删除了条目
```

- `createFile(path, dataType?, text?)`：`dataType` 省略时默认为 `pvf.types.script`，`text` 是脚本可读的初始内容。路径必须非空且不含 `.`、`..` 或空段；路径已存在时报错，不会静默覆盖。
- `copyFile(from, to, overwrite?)`：复制当前暂存状态的最终内容与数据类型，因此同一脚本中先编辑再复制会带上新内容。目标已存在时必须显式传 `overwrite`。
- `deleteFile(path)`：只删除文件本体，不修改 `.lst` 等注册表文件。路径不存在时返回 `false`。需要同步维护列表时用下面的 `pvf.lst`。

### 结构变更与句柄失效

`createFile` / `copyFile` / `deleteFile` 会改变归档的文件表，删除之后的条目索引会被重新编号。因此：

- 删除发生后再使用之前通过 `pvf.find` / `pvf.glob` / `pvf.files` 取得的旧句柄会报错，需要重新查询。
- 预览面板按路径（`changeKey`）而不是文件索引标识变更，行状态区分 `changed` / `added` / `deleted`。
- 应用后需要重新加载归档视图，不能按旧索引原地刷新。

## .lst 列表操作

`.lst` 文件按固定两 token 记录（id、路径）存放资源注册表。`pvf.lst(path)` 返回一个列表句柄：

```js
const lst = pvf.lst("equipment/equipment.lst");

const entries = lst.get();                  // => { "1008": "character/a.equ", ... }
lst.forEach((id, path) => { /* 按文件顺序遍历 */ });
lst.set("1009", "character/b.equ");         // id 已存在则改，不存在则追加
lst.mset({ "1010": "character/c.equ" });    // 批量写入
lst.unset("1008");                          // => true / false
lst.getId("character/b.equ");               // => "1009"，未注册时返回 null
```

- `get()`：返回普通对象，键是 id、值是路径；同一 id 有多条记录时只保留第一条。
- `forEach(callback)`：按 `.lst` 文件顺序调用 `callback(id, path)`。因为 JS 对象会把整数形式的键按数值重排，需要按文件顺序处理时应当用 `forEach`，而不是遍历 `get()` 的结果。回调里可以修改列表，遍历基于进入时的快照。
- `set(id, path)` / `mset(entries)`：id 已存在则原地改写它的路径（保留记录位置与 id 的 token 编码），不存在则追加到末尾。id 可以传字符串或整数（如 `set(1010, ...)`），内部统一按字符串处理。写入某个 id 时，该 id 的重复记录会被合并为一条，因此一个 id 始终只对应一个条目。
- `unset(id)`：删除该 id 的**全部**记录，返回是否真的删除了条目。
- `getId(path)`：反向查询路径注册的 id，未注册时返回 `null`。它只做路径换算，**不要求目标文件存在**。
- 条目路径按 `.lst` 所在目录的相对形式存储，例如 `equipment/equipment.lst` 里的条目写作 `character/a.equ`。`set` / `mset` 同时接受这种相对写法和完整归档路径（如 `equipment/character/a.equ`，会自动换算），并要求目标文件在当前归档中存在，否则报错且不写入，避免登记出悬空条目。

列表编辑属于普通内容修改，会以 `changed` 行进入预览，不需要重新加载归档视图。

## 运行边界

- `file.parse()` 只接受 TypeScript 文件；`text()` / `setText()` 也支持 Unicode 文本文件。
- 结构化文档保留 token 顺序、类型和字符串池编码，不保留空白、注释或原始排版。
- 新建、复制、删除、`.lst` 列表编辑与内容修改一样进入隔离事务，只有点击“应用选中”才会写入当前工作区 Overlay；可用 `pvf.modifiedCount` 查看包括结构变更在内的待应用数量。
- 每次运行最多 5 分钟，同时只能有一个活动运行实例；停止、超时、归档切换和运行异常都会丢弃事务。
- Goja 沙箱不注册 `require`、`process`、`fetch`、Node.js 模块、本地文件、网络或 shell 能力。
- 脚本目录固定为 `os.UserConfigDir()/pvfine/scripts/`，只接受目录内 basename 格式的 `.pvf.js` 文件。

脚本服务事件：`script:state`、`script:log`、`script:progress`。
