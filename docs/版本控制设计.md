# 版本控制

pvfine 的版本控制面向 PVF 内部的逻辑文件，不把完整 `.pvf` 文件作为版本对象。

## 存储

打开并初始化版本控制后，会在源文件旁创建：

```text
Script.pvf.pvfine/
├── repo.db
├── base.pvf
└── objects/
```

`base.pvf` 是唯一的不可变基线；`objects` 使用 SHA-256 内容寻址。脚本和 Unicode 文件保存逻辑文本对象，因为脚本 token 依赖 PVF 字符串池；其他类型保存原始 payload。

当前版本库使用 SQLite 保存提交、父提交、变更路径和对象引用。V1 只提供 `main` 分支，不提供合并和远程同步。

## 操作语义

```text
编辑/批处理  → Working Tree
Ctrl+Enter   → 提交版本，不写 PVF
Ctrl+S       → 保存 PVF 产物，不创建版本
版本面板     → 查看变更、历史、撤销或加载历史版本
```

批处理、创建文件、删除文件和一次编辑操作都会进入工作区变更历史。撤销按一次变更集执行。

Checkout 通过“基线 + 提交变更”重建内存中的归档，不会立即覆盖磁盘上的 PVF。保存后才会生成新的 PVF 产物。

## 兼容限制

V1 使用规范化路径作为文件身份，因此含有重复规范化路径的归档不会启用版本控制。源 PVF 被外部修改后，版本库会拒绝继续关联，避免覆盖未知内容。
