# 索引性能验证

开发版和基准必须使用相同的 Go 编译参数。开发构建使用
`-gcflags="pvfine/...=-l"`，仅关闭项目代码的内联；SQLite 和标准库保持优化。
原来的 `-gcflags=all=-l` 会同时关闭纯 Go SQLite 及其依赖的内联，不能与
默认 `go test` 的耗时直接比较。

## 真实归档强制重建

在仓库根目录运行，`PVF_TESTFILE` 可替换为待测文件：

```sh
PVF_MEMORY_TEST=1 PVF_REBUILD_TEST=1 PVF_TESTFILE=testdata/90CN.pvf \
  go test -gcflags='pvfine/...=-l' ./services \
  -run '^TestLargeArchiveMemory$' -count=1 -v
```

若要复现旧开发版的性能问题，仅将编译参数替换为 `-gcflags=all=-l`。
两种测试应顺序运行，避免相互竞争 CPU 和磁盘。测试末尾的 GC 用于单独测量
存活堆；`forced_rebuild` 不包含这次 GC。

2026-09-21 在同机、同一份 1,057,873 文件归档和同一份索引实现上的各一次结果：

| 指标 | 原开发参数 `all=-l` | 修正参数 `pvfine/...=-l` |
| --- | ---: | ---: |
| 强制重建总耗时 | 54.34 s | 10.41 s |
| 语义加载 | 11.525 s | 3.790 s |
| 文件补齐 | 19.424 s | 2.499 s |
| 创建搜索索引 | 18.907 s | 2.211 s |
| GC 后存活堆 | 437.5 MiB | 437.5 MiB |
| 测试进程累计堆分配 | 32,906.6 MiB | 4,521.7 MiB |

这组结果用于定位编译参数造成的性能差异，不代表三次冷/热缓存验收、
桌面 WebView 物理内存测量或所有平台的性能保证。累计分配不是峰值或物理内存。

修改 Taskfile 后需重新构建并重启开发应用；仅刷新前端不会替换 Go 进程。
可用 `go version -m bin/pvfine` 检查二进制中的 `-gcflags`。
强制重建仍重新解析语义并构建候选数据库，不通过缓存命中跳过重建。
