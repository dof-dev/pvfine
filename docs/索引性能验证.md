# 索引性能验证

开发版和基准必须使用相同的 Go 编译参数。开发构建使用
`-gcflags="pvfine/...=-l"`，仅关闭项目代码的内联；SQLite 和标准库保持优化。
原来的 `-gcflags=all=-l` 会同时关闭纯 Go SQLite 及其依赖的内联，不能与
默认 `go test` 的耗时直接比较。

## 真实归档强制重建

在仓库根目录运行，`PVF_TESTFILE` 可替换为待测文件：

```sh
PVF_MEMORY_TEST=1 PVF_REBUILD_TEST=1 PVF_TESTFILE=testdata/90CN.pvf \
  go test -gcflags='pvfine/...=-l' ./services \
  -run '^TestLargeArchiveMemory$' -count=1 -v
```

若要复现旧开发版的性能问题，仅将编译参数替换为 `-gcflags=all=-l`。
两种测试应顺序运行，避免相互竞争 CPU 和磁盘。测试末尾的 GC 用于单独测量
存活堆；`forced_rebuild` 不包含这次 GC。

2026-09-21 在同机、同一份 1,057,873 文件归档和同一份索引实现上的各一次结果：

| 指标 | 原开发参数 `all=-l` | 修正参数 `pvfine/...=-l` |
| --- | ---: | ---: |
| 强制重建总耗时 | 54.34 s | 10.41 s |
| 语义加载 | 11.525 s | 3.790 s |
| 文件补齐 | 19.424 s | 2.499 s |
| 创建搜索索引 | 18.907 s | 2.211 s |
| GC 后存活堆 | 437.5 MiB | 437.5 MiB |
| 测试进程累计堆分配 | 32,906.6 MiB | 4,521.7 MiB |

这组结果用于定位编译参数造成的性能差异，不代表三次冷/热缓存验收、
桌面 WebView 物理内存测量或所有平台的性能保证。累计分配不是峰值或物理内存。

修改 Taskfile 后需重新构建并重启开发应用；仅刷新前端不会替换 Go 进程。
可用 `go version -m bin/pvfine` 检查二进制中的 `-gcflags`。
强制重建仍重新解析语义并构建候选数据库，不通过缓存命中跳过重建。

## 高级字符串搜索（SQLite）

高级字符串搜索统一使用磁盘反向索引，小归档也不再构建服务层的全量
`StringPoolIndex`。字符串池值只存一份，引用表保存真实池偏移、文件编号、
出现次数、token 类型和文件表字段。普通子串仍使用 Go 的 Unicode 小写规则，
正则仍使用 Go regexp。查询只扫描池记录，不重复解压归档；按路径、文件编号
排序的结果文件编号另存会话库，详情按当前页关联读取。

- 首次使用才建库。构建分批提交，解码时只保留当前块和当前文件的引用。
- 干净归档以加载内容的 SHA-256 和索引版本作为缓存键，缓存命中执行完整性检查。
  索引放在用户缓存目录 `pvfine/advanced-search`，历史缓存预算 2 GiB。
- 缓存使用不可变文件及会话硬链接，历史缓存淘汰不会删除活动会话使用的索引。
  不支持硬链接的文件系统仍可使用会话索引，但不能跨打开复用。
- 未保存归档只建会话库，不发布干净缓存。编辑、结构变化和版本切换会使索引及
  查询游标失效；下一次搜索按需重建。当前尚未对高级引用做逐文件增量更新。
- 查询会话最多 8 个，结果库合计预算 256 MiB，淘汰会删除实际文件；单次查询
  超过可用预算会明确报错。游标包含查询身份，旧游标不能用于新查询或新归档。
- 取消按钮、归档关闭和编辑会取消旧任务并异步释放连接及会话目录；干净缓存保留。
- 这次迁移针对字符串模式。二进制搜索沿用现有实现。

复现：

```sh
PVF_MEMORY_TEST=1 PVF_ADVANCED_TEST=1 PVF_TESTFILE=testdata/90CN.pvf \
  go test -gcflags='pvfine/...=-l' ./services \
  -run '^TestLargeArchiveMemory$' -count=1 -v
```

2026-09-21，同机顺序运行、每场景一次，查询 `npc`，每页 200 个文件：

| 指标 | 测量值 |
| --- | ---: |
| 池字符串数 | 1,643,770 |
| 文件与池偏移引用数 | 26,804,667 |
| 首次建库 | 76.7 s |
| 反向索引文件 | 1,162,321,920 字节（约 1.08 GiB） |
| 已有缓存的完整性检查及打开 | 6.9 s |
| 已有缓存的首次查询（包含检查） | 7.6 s |
| 首次建库之后，普通查询生成结果 | 约 0.8 s |
| Go 正则查询生成结果 | 约 1.1 s |
| 首次建库后连续 10 页，端到端耗时范围 | 8–71 ms |
| 高级搜索后 GC 存活堆 | 约 364 MiB |

这些是服务层真实归档测量，未包含 WebView 物理内存，不是跨机器性能承诺。
终端日志使用 `[pvfine:advanced]`，仅记录条数、容量和耗时，不记录池内容或查询文本。
